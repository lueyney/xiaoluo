# 对齐文档：AI降重页面改造

## 1. 项目上下文
- 技术栈：原生微信小程序，使用 `Page({...})`、`this.setData()`，UI 由 WXML + WXSS 组成。
- 结构特点：页面均使用 `section-card` 卡片布局，按钮、选项等遵循统一样式规范。全局导航栏标题通过 `wx.setNavigationBarTitle` 设置。
- 现状：`pages/rewrite` 页面仍为早期风格，背景渐变色、滑块等交互与当前项目最新设计不符。

## 2. 任务需求
- 目标：将 AI 降重页面 UI 与交互改造成截图所示的卡片式设计。
- 内容：
  - 头部卡片：包含标题、副标题、积分丸子。
  - 功能优势卡片组（智能识别/精准降重/质量保证）。
  - 降重设置卡片，包含学科领域下拉、语言类型选择、降重模式开关、检测平台选择。
  - 输入区域卡片：文本框、字数统计、预计费用。
  - 底部按钮：蓝紫渐变、与写作页保持一致；下方 Tips。
- 行为：沿用现有逻辑（积分计算、降重流程）。新增设置项需与现有数据结构兼容，若无真实接口，暂可模拟。

## 3. 边界确认
- 不涉及后端接口改动；所有数据仍在前端模拟。
- 不调整导航栏、tabBar 等全局配置（已在前序任务完成）。
- 不更改降重流程的业务逻辑，仅更新 UI 和与之匹配的前端数据形态。

## 4. 需求理解
- 需要在 JS 中为新增设置项提供数据源、事件处理、状态同步。
- 预计费用、字数等指标继续使用现有逻辑，根据设置项可能调整描述文案但不改变计算方式。
- 按照截图的层级结构组织 WXML：顶部信息 → 优势卡片 → 设置 → 输入 → 按钮 → 提示。

## 5. 疑问与澄清
- 检测平台、降重模式等具体枚举是否固定？（暂按截图内容写死在前端）。
- “详细要求”文案是否需要可编辑？截图未展示，暂保留现有逻辑的需求输入框即可。

## 6. 初步输出
- UI 重构需要重新编写 `index.wxml`/`index.wxss`。
- JS 需补充：设置项数据（数组、默认值）、事件处理、界面状态更新，与原有 `startRewrite` 联动。
