## 🔍 边界情况处理

### 情况1：轮询未检测到完成

**场景：**
- 生成实际完成了
- 但轮询20次都显示processing
- 或网络问题导致轮询失败

**当前处理：**
```javascript
if (attempts >= 20) {
  console.log('[生成状态] ⏸️ 已达到最大检查次数，停止轮询');
  this.setData({
    generatedContent: '文档生成中...\n\n请稍后前往【文档库】或【订单】查看'
  });
  return;
}

if (attempts >= 3 && err) {
  console.log('[生成状态] ⚠️ 多次请求失败，停止轮询');
  this.setData({
    generatedContent: '✅ 文档正在后台生成\n\n请前往【文档库】查看'
  });
}
```

**结果：**
- ❌ 不显示红点（因为未检测到completed）
- ✅ 用户手动刷新文档库可以看到文档
- ✅ 文档有【新】标记（基于创建时间）
- ✅ 不会误导用户

---

### 情况2：用户在生成中就查看文档库

**场景：**
- 用户点击生成
- 立即切换到文档库
- 文档还在生成中

**当前处理：**
```javascript
// 文档库加载时
const hasNewDocs = wx.getStorageSync('hasNewDocuments');
// hasNewDocs = false（因为还未完成）

if (!hasNewDocs) {
  console.log('[文档库] ℹ️ 无新文档标记，无需清除红点');
}
```

**结果：**
- ❌ 无红点（正确，因为未完成）
- ❌ 无【新】标记（正确，文档还不存在）
- ✅ 等生成完成后，红点会出现在TabBar上

### 情况4：用户多次进出文档库

**场景：**
- 第1次进入：红点清除
- 退出
- 第2次进入：是否重复清除？

**当前处理：**
```javascript
// 第1次进入
hasNewDocuments = true → 清除红点 → 设置为false

// 第2次进入
hasNewDocuments = false → 不执行清除 → 日志：无新文档标记
```

**结果：**
- ✅ 不会重复清除
- ✅ 不会报错
- ✅ 逻辑正确

### 情况5：生成多个文档

**场景：**
- 选择3种文档类型
- 可能部分失败

**当前处理：**
```javascript
// 保存的是选择的数量
lastGenerateCount = 3

// 实际可能只成功2个
// 后端日志：成功生成 2/3 个文档类型

// 红点显示
红点【3】← 显示选择的数量
```

**问题：**
- ⚠️ 红点数字可能不准确（显示3但实际2）

**优化方案：**
- 方案A：显示选择的数量（简单）
- 方案B：后端返回实际成功数量（准确）

**建议：** 暂时使用方案A，后续优化为方案B

### 情况7：页面长时间不刷新

**场景：**
- 生成完成
- 红点显示
- 用户几小时后才查看

**当前处理：**
```javascript
// 【新】标记基于3分钟
const recentDocs = docs.filter(doc => {
  const docTime = new Date(doc.created_at).getTime();
  return now - docTime < 180000;
});
```

**结果：**
- ✅ 红点保持显示
- ✅ 进入后自动清除
- ❌ 【新】标记不显示（超过3分钟）
- ✅ 逻辑正确

---

### 情况8：后端崩溃重启

**场景：**
- 生成中
- 后端崩溃
- 重启后前端继续轮询

**当前处理：**
```javascript
// 轮询失败
fail: (err) => {
  if (attempts >= 3) {
    // 停止轮询
  } else {
    // 继续尝试
  }
}
```

**结果：**
- ✅ 最多尝试3次
- ✅ 失败后停止
- ✅ 不会无限轮询
- ❌ 红点不显示（正确，因为未确认完成）

### 优化2：后端返回实际成功数

**当前问题：**
- 选择3个，实际成功2个
- 红点显示【3】不准确

**改进方案：**
```javascript
// 后端完成时返回实际数量
{
  status: 'completed',
  successCount: 2,
  totalCount: 3
}

// 前端使用successCount
wx.setTabBarBadge({ text: String(successCount) });
```

**优先级：** 🟢 低（不影响核心功能）

---

### 优化3：红点清除时间可配置

**当前：** 固定0.1秒

**改进：**
```javascript
const BADGE_CLEAR_DELAY = 100; // 毫秒，可配置

setTimeout(() => {
  wx.removeTabBarBadge({ index: 1 });
}, BADGE_CLEAR_DELAY);
```

**优先级：** 🟢 低（0.1秒已经合适）
