# 对齐文档：后端打通计划

## 项目上下文分析
- 当前小程序已全面迁移为原生实现，业务数据（积分、订单、生成记录等）仍使用前端模拟值或本地 `storage`。
- 关键页面：`pages/profile`、`pages/orders`、`pages/writing`、`pages/rewrite`、`pages/library` 等均需要真实数据支撑。
- 后端尚未接入，未使用 `wx.request`、云函数或 SDK；身份鉴权逻辑缺失。

## 需求理解
- 目标：与后端服务联通，实现积分余额、订单数量、生成文档数量等指标的真实读取与更新。
- 数据点梳理：
  1. **用户账户**：基础信息、会员等级、注册时间、积分余额。
  2. **积分流水**：积分增加（充值、邀请奖励）、积分消耗（AI生成、AI降重）。
  3. **订单数据**：订单列表、状态流转、支付金额、积分变化。
  4. **文档统计**：AI写作、AI降重生成的文档数量以及存档信息。
- 触发场景：登录加载、页面展示、生成/降重完成、充值/支付后、邀请成功后等需要调用后端接口同步数据。

## 边界确认
- 是否已有后端接口文档和域名？REST / GraphQL / 云函数？
- 鉴权方式：`wx.login` 换取 session、JWT、还是自定义 token？是否需要刷新机制？
- 是否需要离线缓存或失败重试策略？
- 文档内容是否上传至后端存储？若有隐私/容量限制需明确。
- 订单是否需要分页加载、筛选条件？
- 是否区分测试/生产环境，需配置多套域名或密钥？

## 疑问清单
1. 后端服务基础 URL、接口协议及文档是否可提供？
2. 是否已有统一请求封装/SDK？若无，需要自建请求层。
3. 积分单位与精度（整数/小数），是否存在冻结积分等状态？
4. 文档生成/降重记录是否需完整内容上传，或仅存摘要、链接？
5. 订单状态流转流程（创建、支付、取消、退款）及回调机制？
6. 是否需要 WebSocket/轮询以便实时更新？
7. 错误处理与提示规范（如积分不足、服务异常）。
8. 邀请好友奖励的触发流程：由后端回调还是前端提交？

## 下一步
- 梳理通知、积分、订单等数据的前后端同步方案，完善 CONSENSUS/设计，并逐步接入。
