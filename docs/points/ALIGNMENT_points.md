# 对齐文档：积分系统统一

## 现状梳理
- 多个页面使用 `data.credits` 或 `stats.balance` 显示积分，但数值分散：
  - `writing` 页：`data.credits` 未初始化（默认 undefined）。
  - `rewrite` 页：`credits` 默认 1000。
  - `profile` 页：`userInfo.credits` 为 228，`stats.balance` 也写死。
  - `orders` 页：订单模拟数据含积分，但页面顶部统计未展示余额。
  - 登录成功时写入 `userData.credits = 1000`。
- 尚未有统一的积分管理机制；需求要求默认积分 100 分，全局显示一致。

## 目标
- 初始化用户积分为 100 分，存储于本地（后端接通前）。
- 页面显示积分均从统一数据源读取（如 `wx.getStorageSync('userCredits')` 或用户信息数据中）。
- 写作与降重操作消耗积分后同步更新；个人中心、订单等页面刷新时显示最新余额。

## 边界
- 后端尚未接入，暂使用本地存储模拟。后续可无缝替换为接口请求。
- 不改动复杂业务（如订单结算）逻辑，先确保显示一致。

## 疑问
1. 积分消耗是否需要记录详细流水？（目前写作/降重已有扣减逻辑。）
2. 订单页面是否需要展示积分余额？若需要，设计展示方式。
3. 是否需要在登录时重置积分为 100？（需求中“默认积分”理解为首次登录/初始化。）
