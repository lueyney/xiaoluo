# 红点提示系统 - 最终方案

## 📋 需求回顾

**用户需求：**
1. ❌ 取消定时弹窗（不准确，打扰用户）

## 🎯 实现逻辑

### 1. 提交任务后立即显示红点

**文件：** `pages/writing/index.js`

**时机：** 用户点击【开始生成】→ 后端返回PROCESSING → **立即设置红点**

```javascript
// 提交成功后立即执行
wx.setStorageSync('hasNewDocuments', true);
wx.setStorageSync('newDocumentsCount', docCount);

// 立即显示红点
wx.setTabBarBadge({
  index: 1,  // 文档库Tab
  text: String(docCount),
  success: () => console.log('✅✅✅ TabBar红点已设置')
});
```

**优势：**
- ✅ 提交后立即显示
- ✅ 不等待生成完成
- ✅ 不依赖网络轮询
- ✅ 100%可靠

---

### 2. 进入文档库自动清除红点

**文件：** `pages/library/index.js`

**时机：** 用户点击文档库Tab → 进入页面 → 加载文档 → **2秒后自动清除**

```javascript
// 加载文档时检查标记
const hasNewDocs = wx.getStorageSync('hasNewDocuments');

if (hasNewDocs) {
  // 2秒后自动清除（让用户看到红点）
  setTimeout(() => {
    wx.setStorageSync('hasNewDocuments', false);
    wx.removeTabBarBadge({ index: 1 });
    console.log('✅✅✅ TabBar红点已自动清除');
  }, 2000);
}
```

**说明：**
- ✅ 用户**点击Tab进入**文档库
- ✅ 页面加载，显示新文档
- ✅ **2秒后红点自动消失**
- ❌ 不需要用户再次点击
- ✅ 用户有足够时间看到红点

---

### 3. 新文档标记

**显示【新】标记：** 最近3分钟内创建的文档

```javascript
// 检测3分钟内的文档
const recentDocs = docs.filter(doc => {
  const docTime = new Date(doc.created_at).getTime();
  const now = new Date().getTime();
  return now - docTime < 180000; // 3分钟
});

// 添加isNew标记
docs.map(doc => ({
  ...doc,
  isNew: recentDocs.some(rd => rd.id === doc.id)
}));
```

**UI效果：**
- 左上角红色【新】标记
- 脉冲动画
- 3分钟内持续显示

## 💡 设计说明

### 为什么"2秒后自动清除"？

#### ❌ 方案A：点击后立即清除
```
用户点击文档库 → 红点立即消失
问题：用户可能没看清楚就消失了
```

#### ❌ 方案B：手动清除（需要再次点击）
```
用户点击文档库 → 需要点击某个按钮清除
问题：增加操作步骤，体验差
```

#### ✅ 方案C：点击后自动延迟清除（最终方案）
```
用户点击文档库Tab → 进入页面 → 看到红点 → 2秒后自动消失
优势：
  1. 用户有足够时间看到红点
  2. 不需要手动操作
  3. 自动清除，体验流畅
  4. 符合大多数App的设计规范
```

## 🐛 Bug预防

### 1. 红点重复出现
**预防措施：**
- ✅ 进入文档库时清除标记
- ✅ 2秒后移除红点
- ✅ 下次进入不会再显示

### 2. 红点不消失
**预防措施：**
- ✅ 使用setTimeout确保执行
- ✅ 详细日志记录清除过程
- ✅ 成功/失败都有日志

### 3. 轮询失败影响红点
**预防措施：**
- ✅ 红点不依赖轮询
- ✅ 提交后立即显示
- ✅ 轮询仅用于更新底部状态

### 4. 网络问题
**预防措施：**
- ✅ 红点显示不依赖网络
- ✅ 轮询失败3次后停止
- ✅ 更新底部状态说明情况
